# Автопилот

Подаёт заявки сам на Greenhouse, Lever, Ashby и Workable.

```bash
uv run quant-agent autopilot                    # один проход: опрос и оценка в фоне, формы подряд; режим из apply.mode
uv run quant-agent autopilot --mode dry_run     # формы заполняются без отправки
uv run quant-agent answers                      # ответить на вопросы анкет, которых агент не знает
uv run quant-agent apply <uid> --mode assist    # одна вакансия
```

## Режимы

`apply.mode`:

- `assist` — агент заполняет, Submit нажимаете вы; агент ждёт страницу подтверждения `submit_wait_minutes`.
- `auto` — Submit жмёт агент; при reCAPTCHA с задачей — уведомление и ожидание вас.
- `dry_run` — заполнить и снять снимок экрана в `debug/`, ничего не отправлять.

## Проход

Как autopilot в hh-agent: опрос досок, оценка и письма идут в фоне, а заявки подаются сразу из очереди, одна за
другой с паузой `apply.delay_seconds`; после каждой очередь пересчитывается. Очередь пуста и оценка закончена —
программа выходит с итогом: сколько отправлено, оставлено вам, ждут ответов, ошибок и сколько заявок за сегодня.
Повторять — запуском по расписанию (cron, launchd).

**Лимиты**: `max_applications` за `cooldown_months` на фирму, `apply.daily_limit`, `apply.max_per_run`, рабочие часы
(`active_hours`, `weekdays_only`). Подаёт только на вакансии с баллом ≥ `apply.min_score` и с письмом.

## План ответов

План составляется до браузера, по полям формы:

| ATS        | Откуда поля                                                    |
|------------|----------------------------------------------------------------|
| Greenhouse | API (`?questions=true`)                                        |
| Lever      | HTML формы (`cards[…][baseTemplate]`)                          |
| Ashby      | GraphQL страницы формы                                         |
| Workable   | API формы (`/api/v1/jobs/<shortcode>/form`)                    |

Источники ответов по порядку:

1. профиль (`profile`) — имя, почта, телефон, город, ссылки;
2. резюме (PDF по треку, `resume_pdfs`) и письмо;
3. банк ответов `answers.yaml`;
4. вопрос с единственным вариантом-согласием (`apply.auto_consent`);
5. остальное — LLM строго по резюме и фактам.

Чего в фактах нет (GPA, местоимения, регион, другие офферы…), — статус `needs_answers`. Отвечаете один раз
командой `answers`, и ответ подходит для такого же вопроса в формах других фирм. Ответ только для одной фирмы —
ключ «Фирма: вопрос». В `answers.yaml` `Yes` / `No` можно писать без кавычек.

## Заполнение

- Как в hh-agent: «чтение» вакансии, паузы между полями, печать посимвольно, блок образования из профиля.
- После заполнения каждое поле сверяется с планом; не сошлось — `manual` со снимком экрана, заявка не уходит.
- Workable подставляет Address по IP — агент печатает поверх `profile.city`. Workable хранит черновик анкеты:
  уже выбранные варианты агент не трогает, лишние галочки из черновика снимает.
- **Форма `manual` остаётся вам во вкладке**: агент её больше не трогает, следующую заявку открывает в новой
  вкладке, а в конце прохода ждёт, пока вы отправите (заявка станет `applied`) или закроете оставленные формы.

## Браузер

Ваш установленный Chrome (`apply.browser_channel: chrome`, отдельный профиль `apply.profile_dir`) без флага
автоматизации и `navigator.webdriver`: в Chromium из Playwright капчи Cloudflare/hCaptcha крутятся по кругу.
Chrome не найден — агент предупредит и возьмёт Chromium из Playwright (`browser_channel: ""` — сразу его).
Полной маскировки это не даёт; не прошла капча — откройте вакансию в обычном браузере.

## Код из письма

Greenhouse после Submit просит security code из письма. Агент видит поле кода, читает письмо по IMAP (секция `mail`),
вписывает код и снова жмёт Submit — и в `assist`, и в `auto`.

Для Gmail нужен пароль приложения (myaccount.google.com/apppasswords) в `.env`: `IMAP_PASSWORD=…`.
Проверка: `uv run quant-agent mail`. Пароля нет, связь с почтой оборвалась или письмо не пришло за
`mail.code_wait_seconds` — уведомление, код вводите вы.
